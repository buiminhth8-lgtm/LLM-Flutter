# LLM-Studio

LLM-Studio is a local desktop LLM workspace for Windows. The current architecture is:

- Flutter Windows desktop client: `apps/flutter_studio/`
- Python FastAPI backend service: `llm_studio/`
- Backend launch command: `python -m llm_studio.server --host 127.0.0.1 --port 8000`

The backend is a pure Python service. It is not packaged as an exe, it does not use the historical click CLI for service startup, and Flutter does not launch `llm-studio.exe`.

If an old virtual environment still contains `venv\Scripts\llm-studio.exe`, that file is a stale console-script launcher generated by an older editable install. Rebuild the virtual environment if you want to remove it. The current application does not depend on it.

## Recommended Environment

- Windows 11 x64
- Python 3.12 x64
- NVIDIA GPU with CUDA-capable PyTorch, recommended Windows wheel index `cu132`
- Flutter SDK with Windows desktop enabled

Install Python dependencies in layers:

```powershell
python -m pip install --upgrade pip setuptools wheel
python -m pip install -r requirements/base.txt
python -m pip install -r requirements/web.txt
python -m pip install -e .
```

CUDA PyTorch is intentionally not listed in ordinary requirements files. Install it explicitly with the project CUDA script:

```powershell
.\scripts\install_windows_cuda.ps1
```

## Backend Service

Start the backend directly:

```powershell
python -m llm_studio.server --host 127.0.0.1 --port 8000
```

Equivalent module entry:

```powershell
python -m llm_studio --host 127.0.0.1 --port 8000
```

Options:

```powershell
python -m llm_studio.server --help
```

Supported flags:

- `--host`, default `127.0.0.1`
- `--port`, default `8000`
- `--reload`
- `--log-level`
- `--config`

When `--config` is supplied, the service sets `LLM_STUDIO_CONFIG` before starting Uvicorn.

## Desktop Client

Run the Flutter Windows desktop app:

```powershell
.\scripts\flutter_run_windows.ps1
```

The desktop client checks `/health`. If local backend mode and auto-start are enabled, it launches:

```powershell
python.exe -m llm_studio.server --host 127.0.0.1 --port 8000
```

Python detection order in Flutter:

1. Local Python path saved in Settings.
2. `LLM_STUDIO_PYTHON`.
3. `.venv\Scripts\python.exe`.
4. `venv\Scripts\python.exe`.
5. `python` from PATH.
6. Windows launcher `py -3.12`.

Before launching the service, Flutter verifies:

```powershell
python -c "import sys; print(sys.executable)"
python -c "import llm_studio; print(llm_studio.__file__)"
python -c "import uvicorn; print(uvicorn.__version__)"
```

If imports fail, install the project and web service dependencies:

```powershell
python -m pip install -e .
python -m pip install -r requirements/web.txt
```

## Current Capabilities

Implemented:

- First-run local setup and API key creation.
- RBAC roles for viewer, operator, and admin.
- Unified local model repository under `data/models`.
- Model scan, load, current model, unload, and chat binding.
- Multi-turn chat through the selected loaded model.
- Streaming generation and cancellation in the backend; Flutter has SSE parsing and Stop Generation.
- Safe upload handling with filename, extension, and size checks.
- GPU task scheduler for inference, model load/unload, benchmark, vision, finetune, and LoRA merge guards.
- RAG configuration, Chinese chunking, document hashing, and index validation.
- Download, Job, Adapter, Benchmark, Storage, Diagnostics backend modules with truthful capability status.
- Flutter pages for Status, Models, Chat, Downloads, RAG, Adapters, Benchmark, Storage, Diagnostics, Settings, and Setup.

Experimental or partial:

- Download cancellation is cooperative and resumes through Hugging Face cache retry rather than strict pause/resume.
- Benchmark numbers are local development references, not formal hardware ratings.
- LoRA merge remains guarded and should be treated as experimental unless verified in the target environment.
- Flutter is currently validated for Windows desktop first.

Feature truth is exposed by:

```powershell
curl http://127.0.0.1:8000/v1/capabilities
```

## Security Notes

- `trust_remote_code` defaults to `false`.
- API keys are stored hashed by the backend.
- The first plaintext API key is returned only once during setup.
- Flutter currently stores API keys with `shared_preferences`; this is not a high-security Windows credential vault.
- Backend stdout/stderr logs are captured and redacted before display or copy.
- Logs must not contain full API keys, `Authorization`, cookies, passwords, or tokens.
